Externos

Flujo de la Conexión

1. Usuario → Ucampus Uchile
El usuario entra a Ucampus Uchile con sus credenciales.
2. Ucampus Uchile → Usuario
En base a los grupos del usuario, Ucampus Uchile calcula los servicios a los que tiene acceso y sus respectivos permisos (entre los que debería contar el Servicio Externo).
3. Usuario → Ucampus Uchile
El usuario elige el Servicio Externo en el menú lateral.
4. Ucampus Uchile → Servicio Externo
El servidor de Ucampus Uchile realiza una llamada HTTPS a una URL acordada con el Servicio Externo con un parámetro GET llamado ticket.
5. Servicio Externo → Ucampus Uchile
La URL del Servicio Externo deberá llamar a una URL de Ucampus Uchile con el ticket recibido en el punto anterior para obtener un JSON con los siguientes datos del usuario:
  • pers_id: identificador de la persona, usualmente es el rut.
  • permisos: arreglo con los permisos calculados según el grupo del usuario
  • lang: lenguaje del usuario (en: inglés, es: español)
  • theme: tema del usuario (Ej: focus, focus-dark, classic, classic-dark, ...)
  • css: URL con los estilos base de ucampus (según el tema del usuario)
  • time: timestamp en que fue enviado el mensaje
  • mod_id: identificador del módulo que se está llamando
  • gru_id: datos del grupo/curso si corresponde
  • id_externo: opcional, corresponde al Pasaporte
  • session_hash: string que identifica el estado del usuario durante una sesión. Si cambia parte de su información de grupos y/o permisos, cambiará el valor.
Luego el Servicio Externo deberá responder con una de las siguientes opciones:
  • URL en caso de éxito: Ucampus Uchile se encargará de redirigir al usuario a esta URL (que debiera venir con algún tipo de ID de sesión para recuperar los datos del usuario).
  • Mensaje en caso de error: Mensaje de texto que indique cual es la razón por la cual no se le permite acceder al servicio.
Acá puedes ver un ejemplo en PHP de como debiera validar la información el script externo: externo.php
6. Ucampus Uchile → Usuario
Ucampus Uchile le envía al usuario la redirección a la URL enviada por Servicio Externo o le muestra el mensaje de error.
7. Usuario → Servicio Externo
El navegador del usuario va a la URL enviada por Servicio Externo, y ahora conversa directamente con éste (quien debiera, usando el ID de sesión, retomar los datos del usuario).

Requisitos Técnicos

1. HTTPS

Todo el contenido de Ucampus Uchile se transfiere en forma encriptada bajo el protocolo https, por ende para que los navegadores no bloqueen el contenido del Servicio Externo este también deberá usar el mismo protocolo. Esto además asegura que la comunicación no pueda ser interceptada por terceros.

2. CSS

Para lograr el efecto de un servicio integrado y coherente a la plataforma, el Servicio Externo será cargado en un iframe dentro de Ucampus Uchile, cuyo contenido deberá incluir la hoja de estilo que viene en la variable css <stylesheet> dentro del tag <head>:

<link rel="stylesheet" media="all" href="{valor_en_variable_css}" />

Esto redefinirá el estilo para varios de los elementos estándares html:

  • Títulos: <h1>, <h2>, <h3>, <h4
  • Listas: <ul>, <ol>
  • Tablas <table>
  • Elementos de formularios <form>

Además quedarán disponibles las siguientes clases:

  • <a class="boton"> El link quedará con el look&feel de un botón, que además puede potenciarse con las siguientes clases adicionales: ok (verde), warn (naranjo), wrong (rojo).
  • <table class="form"> Para tablas dentro de un formulario.
  • <form class="buscar"> Para hacer pequeños gadget de búsquedas
  • <ul class="modulo"> Para hacer pestañas de menus.
  • <ul class="submodulo"> Para submenus.

Para tablas existen 2 clases adicionales:

  • <table class="form"> Es una tabla tipo formulario para ingresar información.
  • <table class="detalle"> Es una tabla informativa con datos para el usuario.

Dado que Ucampus Uchile soporta temas que modifican la paleta de colores (como oscuro, claro, etc.), entre las variables que se envián al servicio externo va theme que indica el tema activo del usuario. Esto es importante para poder aplicar los estilos correctos y coherentes al resto de la plataforma.

3. Javascript

Dado que el contenido del Servicio Externo es variable, Ucampus Uchile debe variar el tamaño del iframe para que no se genere un doble scroll, para lo anterior es necesario que el Servicio Externo incluya el siguiente script en todas sus páginas: 

<script type="text/javascript" src="https://ucampus.uchile.cl/b/externos/resizer.js"></script>

Requisitos Operativos

Grupos y Permisos

Se debe definir quien puede acceder al servicio en base a los grupos a los que pertenece en Ucampus Uchile, y sus respectivos permisos (que serán los enviados al Servicio Externo según el flujo de conexión).

Contraparte Técnica

Se debe establecer una contraparte (con correo electrónico) a quien Ucampus Uchile le enviará alertas automáticas cuando el Servicio Externo no esté respondiendo correctamente (para que corrija la situación, o en caso contrario se dará de baja el servicio).
